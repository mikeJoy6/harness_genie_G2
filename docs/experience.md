# 系统提示分层与经验系统

2026-11-16。代码：[harness/loop.py](../harness/loop.py)（`build_system`）、[harness/experience.py](../harness/experience.py)、[harness/tools/experience.py](../harness/tools/experience.py)；经验在 [experience/](../experience/README.md)。

## 为什么改

旧 SYSTEM 把四种东西搅在一段里：机器人的事实、硬规则、工具路由（“指向用 point_at_object”）、任务配方（“拿起来 = 五步”）。问题：

- **工具路由和工具说明重复，一改就不一致。** 2026-11-14 模型拿 `touch_object` 去“放”鼠标，就是被“碰一下用 touch_object”这条引过去的。
- **配方只会越堆越长**，而且只有步骤、没有原因，模型没法迁移到新任务。
- **缺事实和原则**：手里的东西不在碰撞检查里、没有“放下”工具、说“完成”前要验证。
- **有的规则把模型往错的方向推。** “不要反复重试同一个失败的运动”被理解成“换个工具硬凑”。

## 怎么分

| 放在哪 | 放什么 | 例子 |
|---|---|---|
| 程序（gateway / backend） | 违反了就危险的，必须强制 | touch 最后一段慢速、六维力碰到就停 |
| SYSTEM | 事实、硬规则、工作方法，加经验目录 | 只有右手有夹爪；只有 executed 为 true 才能说动了 |
| 工具说明 | 这个工具做什么、参数怎么填 | “最近的”是列表第一个 |
| 经验（按需读） | 推荐做法，可以变通 | 递东西：从正上方下来，在离手约 4 厘米处松开 |

“接触人”的原则只讲意图：**用户要求时（击掌、碰拳、递东西）才接触人；没要求时，不让夹爪或手里的东西靠近人。** 具体从哪个方向接近，写在各自的经验里：递东西从上方下来，击掌从正面过去。早先的草稿写成了全局规则“靠近人时只能从上方竖直下来”，那样就没法击掌了（用户指出），所以改成现在这样。

## 经验系统

- **SYSTEM 末尾自动生成目录**，每条一行：`- 名字:什么时候用`。
- **`read_experience(name)` 读全文**，模型觉得相关才读。
- **`propose_experience` 提议新经验**，存进 `experience/pending/`，**人审核后才生效**（`scripts/experience.py approve`）。模型的自我总结可能是错的，比如 11-14 它确信“已经放到您手上了”。
- 经验每条固定五部分：适用场景、原则、做法、常见坑（附出处）、怎么确认成功。测试 `test_real_experience_files` 检查格式，并检查正文里提到的工具都真实存在，防止工具改名以后经验里还写着旧名字。

第一批 4 条：`pick_up_object`、`handover_to_person`（未在真机验证）、`high_five`、`photo_of_group`。状态按真机 trace 如实写。

## 跨指令的状态

交互模式下（`run_task.py` 的 `Session`），多条指令共用一个 Gateway：

- `holding`：按夹爪动作推测手里拿着什么。`touch_object(gap 0)` 下探到某个物体之后闭合 = 拿着它；张开 = 空。没有验证，在 `get_robot_state` 和 gripper 的结果里报给模型。
- 物体编号表留着（120 s 过期）。
- 新指令前面附上最近 5 条问答（只有文字，没有工具调用）。

`max_moves_per_command` 从 8 调到 12：“拿起来放到我手上”要 10 次运动，8 次时会停在夹爪张开、悬在半空的状态。

## 场景测试结果（2026-11-16，deepseek-flash，每个场景 3 遍）

`python3 scripts/run_scenarios.py --variant ...`，6 个场景：拿起、递到手上、分两条指令先拿后递、击掌、只问不动、合影。

| 变体 | must 全过 | 说明 |
|---|---|---|
| baseline（旧 SYSTEM） | 15/18 | 递鼠标 3 遍里 2 遍用 `touch_object` 碰人手，和 11-14 真机一样 |
| no_experience（新 SYSTEM，没有经验） | **10/18** | 比旧的还差：配方搬走了，拿起时 2/3 忘了先张开夹爪；但“完成前验证”从 0 变成了 2/3~3/3 |
| new（新 SYSTEM + 经验） | **18/18** | 每次都读了相关经验；递东西从上方下来、松开后用 `find_objects` 确认 |

要注意：

- 每个场景只跑 3 遍，样本小。
- 递东西那条经验是看着这次的失败写的，场景测的正是它，有“对着考题写答案”的成分。要看泛化，得加没写过经验的新任务。
- 假世界很宽松：没张开就闭合也算抓起来了。
- 真机都还没跑。
