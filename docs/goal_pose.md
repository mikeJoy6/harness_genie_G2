# 手臂终点姿态:保持 / 舒适(三角函数)/ 放松

问题:`approach_object`、`move_arm_end` 以前终点姿态 = 当前姿态(`full` 模式锁 6 维),末端“只会平移”;目标往身体中线一靠,IK 就无解,`via_then_rrt` 在终点检查那一步直接放弃(`目标不可达:多种子 IK 解不出,不搜索`)。

做法:**规划之前先定终点姿态**,定好后照样交给积分笛卡尔直线 → `via_then_rrt`,规划器一行没改。代码 [harness/motion/goal_pose.py](../harness/motion/goal_pose.py)。

## 三种来源

| 策略 | 怎么定 R | 特点 |
|---|---|---|
| `keep` | 当前姿态 | 以前唯一的做法;小幅移动时手腕不乱转 |
| `comfort` | 三角函数闭式推 + IK + 肘拉到位 + 打分 | 构型最舒服;腕关节范围窄(j6 ±58°、j7 ±88°),有的点几何解超出手腕范围 |
| `free` | 只管位置:先从当前构型积分(`pos` 模式),不行多种子 IK | 能到的点最多;姿态随它,可能别扭 |

按顺序试,第一个规划成功的就用([configs/harness.yaml](../configs/harness.yaml) `motion.goal_orientation`):

| 工具 | 默认顺序 | 理由 |
|---|---|---|
| `approach_object` | comfort → keep → free | 去物体上方:先求舒服 |
| `move_arm_end` | keep → free | “上抬 10 厘米”:先保持手腕姿态 |
| 模型给了 `rotate_deg` | 只按它(exact) | — |

结果里 `plan` 摘要会写“终点姿态 舒适(基面 30°,舒适分 0.8)”之类,看得出用了哪种。

## 指定工具朝向:`tool_axis`

用户说“夹爪竖直朝下 / 朝前”时,模型填 `tool_axis`(`down / up / forward / backward / left / right`),
程序用 `roll_locked(当前姿态, 方向)` 算出终点姿态(roll 不自转)。**不让模型自己换算欧拉角**:真机上它把“朝下”算成绕 z 转 36°,工具轴倾斜一点没变(77.9° → 77.9°)。
`get_robot_state` 直接报 `tool_axis` 和 `tool_tilt_from_down_deg`(0 = 正朝下)。

### 原地转不到:自己后撤着转

用户只说“让夹爪竖直朝下”,不说撤多少。`move_arm_end(tool_axis=down)` 原地规划不出来时,后端
[`_plan_tilt_retreat`](../harness/backends/ros.py) 调 [`tilt_search`](../harness/motion/goal_pose.py):

1. 后撤方向 = 末端 → 肩,只取水平分量(往身体收)。
2. 后撤距离 r = 0、5、10 … 30 cm(`motion.tool_axis_retreat`):每个 r 先试完全转到朝下;不行就二分(5 次)找最多能转几成,下一步从这个解接着找(构型连续)。
3. 哪一步完全转到了就停(撤得最少);都转不全取转得最多的。只看 IK,碰撞交给后面的规划器。
4. 找到的位姿一次规划过去(直线 → via_then_rrt);gateway 按实际终点再查一次工作范围。结果报 `retreat_m`、`tilt_fraction`(1 = 完全到位)。

真机日志那次的关节角(右臂离竖直 77.9°):原地无解 → 后撤 10 cm 完全朝下,离竖直 1.0°、自转 0.2°,搜索 0.26 s。

## roll 锁住:放开 pitch / yaw,手腕不自转

工具轴(末端 Z)朝哪 = pitch / yaw,由 comfort / free 选;绕工具轴转多少 = roll,**一律锁住**:
[`roll_locked(R_now, 新工具轴, roll_deg)`](../harness/motion/goal_pose.py) 把当前姿态只做“Z 轴转到新方向”的最小转动,X、Y 跟着带过去,不绕工具轴自转;
模型给了 `wrist_roll_deg`(`approach_object` / `move_arm_end` 的参数,用户明确说“手腕转 30 度”时才填)再绕新工具轴转这么多。

为什么:roll 基本不影响够不够得着,但以前舒适姿态的 roll 用“基面法向”定,和当前手腕无关,真机上手腕会莫名转一大圈。

离线对比(右臂,`find` 腰姿态,30 个随机点 + 真机那次手机上方):

| | 能到 | 关节总变化中位 | 腕 j5+j7 变化中位 | 绕工具轴自转中位 |
|---|---|---|---|---|
| comfort 旧(基面定 roll) | 21/31 | 308° | 54° | **98°** |
| comfort 新(锁 roll) | 21/31 | 252° | 48° | **0°** |
| free 新(锁 roll) | 31/31 | 168° | 9° | 0° |

真机那次目标 (0.798, −0.077, 1.012):旧算法自转 −121°、关节总变化 350°;新 0°、262°(真机记录关节总行程 387.7°)。

## 舒适姿态怎么算(`ComfortPose`)

思路来自 `~/genie_framework/DEVLOG.md` 7721~7888 行“二次推导”(那里是 G1、够不着时的指向),改成“够得着”的版本。全在手臂根系 `arm_base_link` 里算。

G2 手臂几何(URDF 零位):肩心 S = link2 原点,肘 link4,腕心 W = link6/7 原点,末端 T = `arm_*_end_link`。
L1 = |S−肘| ≈ 0.332 m,L2 = |肘−W| ≈ 0.278 m,c = |W−T| = 0.090 m。末端坐标系 **Z 轴 = 腕心→末端**(工具轴)。

1. **腕心离肩多远**:d 取两个临界的中值——肘弯 90° 时 √(L1²+L2²),伸直时 L1+L2(×0.97 留余量)。候选 d 再取 1/4、3/4 处。
2. **工具轴偏多少**:三角形 S-W-T 三边 b=|S−T|、c、d 已知,余弦定理 cosθ = (b²+c²−d²)/(2bc),θ 是 T 处“T→W”和“T→S”的夹角。
3. **定基面**:S、W、T(和肘)共面,这个面绕 S→T 转 φ。φ=0 是“广义水平”(面和水平面的交线 ⊥ S→T),往外(左臂 +y、右臂 −y)一侧;候选 φ = 0、30、60、90、120、−30、−60°。
   W = T + c·(cosθ·a + sinθ·e),a = T→S 单位向量,e = 面内 ⊥ a 的方向。
4. **姿态**:Z = W→T;roll 用 `roll_locked` 锁在当前手腕上(见上一节)。没有当前姿态时才用基面法向当 Y。
5. **肘**:S-E-W 三角形(两边 L1、L2)定肘的目标点 E*,在同一个面里、往外 / 往下那侧。IK 解出来后在零空间(末端不动)把肘拉向 E*,再精修末端。
6. **打分**:各关节离限位中点的归一化距离平方和(越小越舒服),所有候选里取最小。

## 离线对比(只用 URDF,不碰机器人)

左臂,实测构型出发,前方随机 40 个点(x 0.35~0.8、y −0.25~0.6、z 0.75~1.2,腰全零):

| | 能到 | 舒适分中位 | 平均耗时 |
|---|---|---|---|
| keep | 22/40 | 1.56 | 50 ms |
| free | 24/40 | 1.37 | 454 ms |
| comfort(7 φ × 3 d) | 18/40 | **0.87** | 237 ms |

两者都能到的 18 个点里,comfort 更舒服的 14 个。候选加密到 12 φ × 5 d 能到 20/40,但 656 ms,不划算;靠“comfort → keep → free”串起来补。

用 `poses.yaml` 的 `find` 腰姿态:右臂去 (0.55, 0.15, 0.95)(往中线靠),keep 无解,comfort / free 有解;真机那次手机上方 (0.718, −0.167, 1.007) 三种都有解。

## 没验证的

- 真机没跑过。离线没有碰撞检查(真机 `valid` 会调 MoveIt),候选里撞的会被跳过,耗时会更长。
- 打分只看关节离限位中点;“工具尽量朝下”留了 `tool_hint` 接口(`ComfortPose.score`),还没接到配置。

## 规划失败时的接触兜底(`contact_fallback`)

点云把桌上的东西、人的手都扫进 octomap,所以“去接触 / 贴近物体”的目标本身就在障碍里,正常规划永远失败。现在手臂规划(所有姿态策略、后撤都试过)仍失败时,**先不报失败**:

1. 沿“目标 → 当前末端”往回,按 `backoffs_cm`(3、5、8、12、16、20、25、30 cm)从近到远找接近点;对每个点做一次完整的正常规划(同样的姿态策略,全程整机碰撞检查),第一个成功的就用 → 离目标最近的可达点。
2. 执行([`_execute_contact`](../harness/backends/ros.py)):先走第 1 段;到了以后从**实际位置、保持实际姿态**走笛卡尔直线到目标,`check_collision=False`([`plan_cartesian`](../harness/motion/arm_motion.py) 新参数),速度 `speed_m_s`(0.03 m/s),长度超过 `max_unchecked_m`(0.30 m)就停。
3. 结果仍是成功,但带 `precontact_xyz_m`、`unchecked_m` 和 note“最后这段没有检查外界碰撞(会接触物体)”,模型要如实告诉用户。

注意:MoveIt 的 `/check_state_validity` 自碰撞和外界碰撞是一起查的,所以最后这段**自碰撞也没查**;它很短、从一个已验证不撞的姿态出发、末端走直线,风险小,但不是零。

替身手臂验证(目标周围 6 cm 内都是障碍):3、5 cm 的接近点不行,选了 8 cm;执行后末端到目标,最后一段 `check_collision=False`。**真机没跑**。

## 手臂够不着:先动腰(`body_assist`)

规划顺序的最后一步:正常规划 → 同位置最接近的朝向(容差 15°)→ 后撤着转(只给朝向时)→ 接触兜底(目标够得着但在点云里)→ **动腰**。

[`body_assist_search`](../harness/motion/goal_pose.py):只改 body 第 3 关节(前倾,正 = 往前)和第 5 关节(转腰,正 = 向左),组合按 |前倾| + |转腰| 从小到大试(前倾 5~30°、转腰 0/±10/±20°,`motion.body_assist`),在 URDF 上算“这个腰姿态下手臂 IK 有没有解”(给了 tool_axis 就要离它 ≤ 15°),第一个有解的就用。
[`_plan_body_assist`](../harness/backends/ros.py) 规划腰的运动(整机碰撞检查);执行时先动腰,到位后从新姿态重新规划手臂(可用接触兜底,不再动腰)。结果带 `body_assist`、note。

注意:**右臂够不着时腰往右转反而更远**(右肩往后走);前倾才把肩送向前方。

替身验证(“低头找鼠标,拿起来”那次的腰和右臂,鼠标上方 25 cm 夹爪朝下):前倾 10° 就够,搜索 0.2 s;先动腰再规划手臂,末端到目标差 3 mm,夹爪离竖直 5.4°。
